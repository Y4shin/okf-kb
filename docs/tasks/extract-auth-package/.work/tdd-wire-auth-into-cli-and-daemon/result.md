## Divergence from plan

1. **`packages/cli/package.json` devDependencies do not list `@okf-kb/fs` / `@okf-kb/daemon`.** The task prose assumed they were already present, but the current file only lists `@types/node`, `typescript`, and `vitest`. Per the instruction "Keep devDependencies unchanged", I left them as-is. Tests still pass because the workspace symlinks these packages at the root `node_modules`, so Vitest/TypeScript resolve them. A standalone `npm install` inside `packages/cli` would not install test-only workspace packages; if that becomes a requirement, add them to `devDependencies`.

2. **`packages/pi-adapter/extension/package.json` was not edited.** It still declares `file:../../daemon` but does not declare `file:../../auth`. TypeScript resolves the new direct `@okf-kb/auth` import via the existing `../daemon` project reference (which itself references `../auth`). Because `npm run typecheck` passed, I did not add `file:../../auth` per the "add only if needed" instruction. This leaves a latent packaging correctness gap: a published extension would be missing a direct dependency on `@okf-kb/auth`. Since the extension is private and the slice scope was to switch the import, this is acceptable here, but should be fixed when the extension is prepared for publishing.

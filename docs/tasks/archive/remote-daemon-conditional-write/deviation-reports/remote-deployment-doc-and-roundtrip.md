### Out-of-scope changes
- **`groups` array order in doc JSON examples (minor, cosmetic deviation):** `docs/remote-deployment.md` shows the `GET /` capabilities response with `"groups":["read","search","write","localFs","indexAdmin"]` (lines 97, 104, 300). However, `Object.keys(fullBindings)` in `@kb/protocol` (`records.ts:91-96`) returns `['localFs','read','search','write','indexAdmin']` — `localFs` is first. The arch spec (line 81) says "Derive `groups` from the keys of `fullBindings`", and the daemon does exactly that (`server.ts:100` `Object.keys(fullBindings)`), so the *runtime* order is `localFs`-first. The doc's example JSON has a different element order (read-first). This is a **cosmetic inaccuracy in the doc's example output**, not a code bug — the actual daemon would emit `["localFs","read","search","write","indexAdmin"]`. The `remote-deployment-doc.test.ts` test only checks for the literal string `groups` (line 103), not the array order, so this is uncaught by the auto-gate. A reader who copy-pastes the `curl` example and compares to live output would see a reordering. **No functional impact** (JSON arrays are order-tolerant for a capabilities listing; clients don't depend on the order).
- **Skill-test assertion inversions (expected, not scope creep):** Three existing skill tests were changed from `expect(lc).not.toMatch(/kb_put|kb_delete/)` to `expect(lc).toMatch(/kb_put/)` + `/kb_delete/` + `/remote/` + `/isremotekb/` (`kb-curate-skill.test.ts:172-181`, `kb-research-skill.test.ts:254-262`, `kb-save-session-skill.test.ts:256-264`). This is the necessary test update for the added skill notes — the prior assertion ("no kb_put") was incompatible with the new one-line remote note. This is in-scope (the slice doc's "Affected files" lists the skills; updating their tests is implied).
